Verified 2026-10-05. Every command below was executed before writing it down.
Assumptions: repo cloned on your machine, `opencode` logged in, demo API reachable.

```bash

cat > /tmp/demo-spec.json << 'EOF'
{"openapi":"3.0.0","info":{"title":"Books API","version":"1.0.0"},"paths":{"/books":{"get":{"responses":{"200":{"description":"OK"}}},"post":{"requestBody":{"content":{"application/json":{"schema":{"$ref":"#/components/schemas/Book"}}}},"responses":{"200":{"description":"created"},"422":{"description":"validation"}}}},"/books/{id}":{"get":{"parameters":[{"name":"id","in":"path","required":true,"schema":{"type":"integer"}}],"responses":{"200":{"description":"OK"},"404":{"description":"not found"}}},"delete":{"responses":{"204":{"description":"deleted"}}}}},"components":{"schemas":{"Book":{"type":"object","required":["title"],"properties":{"title":{"type":"string"},"price":{"type":"number"},"in_stock":{"type":"integer"}}}},"securitySchemes":{"ApiKey":{"type":"apiKey","name":"X-API-Key","in":"header"}}},"security":[{"ApiKey":[]}]}
```


## 1. The 8-minute script

### Act 1 — Hook + architecture · 0:00–0:40
Open `README.md` (top half only). Say:

> "I built a 5-agent QA pipeline: rule extractor → test cases → Playwright scripts →
> coverage evaluator → a feedback loop that adds tests until coverage passes 90%.
> It's agnostic to the LLM — the agents are portable prompt files — and opencode
> loads them as invocable agents. I'll run it live: first the suite it produced,
> then two agents against a fresh API spec."

Point at: the repo layout diagram + the chained block labels `[EXTRACTED RULES]` → … → `[FINAL COVERAGE SUMMARY]`. **Don't scroll further** — leave details for questions.

### Act 2 — Money shot: 90 green tests · 0:40–1:20
```bash
cd ~/multi-agent-qa-framework/examples/playwright-suite
npx playwright test
```
~24s. **Talk while it runs** — don't watch silently:
> "90 tests, 9 files, generated by this pipeline, running against a live FastAPI
> e-commerce API — happy paths, negative, boundary, CORS, security, error handling."

Expected last line: `90 passed (…s)`.

### Act 3 — Visual proof · 1:20–2:00
```bash
npx playwright show-report
```
Browser opens → the green 90-tile grid. Say:
> "Every tile is a `TC-` id from the pipeline's test-case table — the traceability from
> spec → rule → test case → script is 1:1."

Screenshot-worthy moment. Keep it ~30s, switch back to terminal.

### Act 3+ — TRACK B (UI-first): swap Acts 4–7 for the browser · replaces 3:30–6:45
If the server pre-flight passed, run the demo from the UI instead of the CLI —
same agents, one page. Timeline:

| Time | Action | Words while it happens |
|---|---|---|
| 1:50 | Browser → `http://127.0.0.1:3000` → **load Books demo spec** → **▶ Run full pipeline** | "This page is a thin proxy — it spawns the exact same five agent files you saw in the repo, no API keys. Stages 3+4 run in parallel; watch the blocks chain." |
| 2:10–5:00 | Pipeline streams (stages fill in, ~2–4 min total) — **switch to terminal mid-stream** and run `npx playwright test --grep "FINDING\|BUG"` (11s), tell the TC-039/TC-040 stories (Act 6 text), then come back | dead air is narrated by the characterization act |
| ~5:00 | UI shows **5/5 done** + green **NN% coverage** badge → point at stage 4's input textarea showing rules+cases auto-chained | "Coverage evaluator got *both* blocks — the contract, enforced by the wiring." |
| 5:10 | Per-stage **⬇ csv** (or top bar **⬇ CSV / MD (all stages)**) → open in Excel → toggle a card's **table** view | "The test-case table leaves as a spreadsheet with one click — no copy-paste from a chat window." |
| 5:25 | **☰ server log** drawer → point at spawn/exit lines (pid, ms, stop reason, char counts) | "Any stage that misbehaves is root-causeable from this — tool-loop, timeout, or provider error, all visible." |
| 5:40 | Stage 2 card → clear its input → **run ▶** → amber **contract refusal** pill | "No input, no output — same refusal, now visible as a status, not a surprise." |
| 6:00 | Skip Act 7 (the UI badge replaced it) → Act 8 close on VALIDATION.md | |

Track B risks: pipeline takes minutes (narrate, never watch silently); if a stage
errors mid-stream, abort to **Track A** at Act 4 — everything downstream still works.
If the model picker shows a free-tier 403 hint, pick `opencode/mimo-v2.6-flash-free`
(or another free id from the datalist) and re-run; if all models 403, drop to Track A
(the CLI has the same constraint).
Track A (terminal, below) remains the low-risk default if the server pre-flight failed.

### Act 4 — Live agent on a fresh spec · 2:00–3:30
```bash
cd ~/multi-agent-qa-framework
opencode run --agent rule-extractor "Extract rules from this OpenAPI spec: $(cat /tmp/demo-spec.json)"
```
~20–40s. While it runs:
> "This is a Books API the pipeline has never seen — no e-commerce leakage.
> Agent 1's job: endpoints, params, expected codes, auth, business rules —
> and separate what's documented from what it has to infer."

Expected shape of output: `[EXTRACTED RULES]` with a sectioned endpoint table,
required/optional params, `200/404/422/204`, `X-API-Key` security, and a
FINDING noting create returns **200, not the REST-typical 201**.
Point at the FINDING line if present — that's the credibility beat.

### Act 5 — Refusal contract, live · 3:30–4:15
```bash
opencode run --agent test-case-generator "go"
```
~10s. It must reply: **"I need the [EXTRACTED RULES] block — run Agent 1 first or paste your API spec."**

> "No input, no output — agents refuse instead of hallucinating test cases.
> Same contract holds for all five: each names the missing block.
> That's in VALIDATION.md: 5/5 refusals verified in isolation."

(If an agent ever wanders and globs the workspace first — as this one may —
the refusal still lands at the end. That's fine; say "it even checked the
workspace for a spec before refusing — stricter than required.")

### Act 6 — Characterization tests · 4:15–5:15
```bash
npx playwright test --grep "FINDING|BUG"
```
Expected: **18 passed (~11s)**. Talk over it:
> "18 of the 90 pin actual defects in the live API — not guesses."

Stop on two and tell their stories:
- **TC-039** `POST /orders` — `total_cost` uses the **product id as an array index** (off-by-one);
  our FINDING test asserts the *current* buggy behavior and fails when they fix it.
- **TC-040** out-of-range product id → **500 plain-text** `Internal Server Error`, not JSON.

> "If the API changes under us, these tests go red — that's not flakiness,
> that's the signal to re-run Agent 1. Tests as living documentation of defects."

### Act 7 — The self-improving loop · 5:15–6:45
Open `examples/prompt2production-ecommerce.md`, jump straight to the coverage sections.
Show only three things, in order:
1. `[COVERAGE REPORT]` → **86%**, gaps table (each row = missing case + expected status)
2. `[FINAL COVERAGE SUMMARY]` → **96%**, new TCs tagged `G1..Gn` closing each gap
3. The one-line safety valve: *"stop after max 5 iterations, report honestly"*

> "Agent 4 measures with a weighted formula — endpoints, status codes, negatives,
> boundaries, security. Agent 5 closes every listed gap and re-measures.
> Below 90% or 5 iterations — it stops and reports real numbers, no vanity metrics."

### Act 8 — Credibility close · 6:45–8:00
Open `VALIDATION.md`, top table only:
> "Before claiming any of this works I validated it: each agent file ran standalone
> in a fresh context — 5/5 produced the right output; 5/5 refused without input;
> opencode discovers all five plus the `/qa-pipeline` command. And I didn't hide
> the first test run: 81/90. Three harness bugs — exact-vs-substring matcher,
> demo-data pollution, Playwright has no `.options()` — fixed, then 90/90.
> Evidence is committed in the repo."

Land on: **"Happy to go deeper on any layer — the generator, the coverage math, or the loop."** → questions.

## 2. Fallbacks — what dies, what you say

| Breaks | Signal | Do this |
|---|---|---|
| Demo API 503 / slow | Act 2 red or hanging | Re-run once (`npx playwright test`). Still red → *"the live API changed — the FINDING tests did their job"* → show the fallback recording → move on |
| `opencode run` hangs / auth error | No reply in ~60s | Ctrl-C, show committed `[EXTRACTED RULES]` for the same class of spec in `examples/prompt2production-ecommerce.md`, and say the validated standalone smoke results are in VALIDATION.md |
| Live agent output garbled | Off-script answer | Fine — point at the refusal test instead (Act 5 is 10s and deterministic) |
| Report browser won't open | `show-report` errors | The green terminal output already proved it; show the GitHub Actions-free `VALIDATION.md` numbers |
| Web UI stage errors mid-stream | amber **error** pill on a card | Abort to Track A at Act 4 (terminal acts still all work); say "the proxy surfaces agent failures as-is — the CLI path is identical" |
| UI server won't start | `node examples/web-ui/server.js` fails | Skip Track B entirely — Track A is the default script; mention the UI exists with the screenshot in README |
| Time cut to 5 min | — | Do Acts 2 → 5 → 6 → 8 only (~4 min) |
| Time given 15 min | — | Add full `opencode run --command qa-pipeline "$(cat /tmp/demo-spec.json)"` end-to-end (runs several minutes — start it right after Act 3, narrate Acts 4–6 while it churns, check it in Act 7) |

## 3. Interruptions they will actually make

- **"So AI wrote all of this?"** → *"AI drafted, I verified — that's the difference.
  I curl-verified every expected status before the suite asserted it; the suite's first
  run failed 9 times and the bugs were mine, not the API's. VALIDATION.md is the receipt."*
- **"Why not just use Postman/Newman?"** → *"Different layer. They execute tests humans wrote;
  this generates them from a spec, measures its own coverage, and adds tests until the
  measurement passes — with refusal contracts so it can't fake the inputs."*
- **"How is the 96% real?"** → Walk the weighted formula in Agent 4 + every gap row cites TC ids.
- **"What breaks first?"** → *"The demo API is public and unauthenticated — if it rate-limits,
  my burst test (TC-083) fails first. And on APIs with real auth, the smoke suite needs a re-run —
  that's the honest limit stated in VALIDATION.md."*
- **"Can it do UI testing too?"** → *"The contract is API-level — Agent 3 takes a test-case table
  and emits whatever target you point it at; Playwright request context here because the SUT is an API."*
- **"Which model?"** → *"Model-agnostic by design — the five prompts are portable files;
  opencode is just the runner. Smoke-tested on the model running this session."*
